## 结论

对 Hass 等「既要科学、又要对内提供服务」的主机，必须在交换机上做**目的分路**（ACL 3002 + PBR deny node），否则 VPN/局域网访问会出现**路由不对称**。

H3C `if-match acl` **只认 permit**；同 ACL 写 `deny destination` **无效**（详见主文档 §2）。

## 两种 VPN

| 类型 | 实现 | 对端 / 网段 | 说明 |
|------|------|-------------|------|
| **WireGuard** | 241 `wg-easy` | 客户端 **`10.0.0.0/24`**；Endpoint `vpn.home.yushuangyang.top:51820` | AllowedIPs：`192.168.1.0/24`、`10.0.0.0/24` |

## Hass 出站场景（按目的）

| 优先级 | 目的 | 场景 | 是否进 mihomo |
|--------|------|------|----------------|
| 1 | `192.168.0.0/16` | 家局域网、Nginx `.241`、办公室 IPsec `.5.0/24`、交换机 `.254` | **否**（ACL 3002 → deny node） |
| 2 | `10.0.0.0/8`（WG 实际 `/24`） | WireGuard 回包 | **否** |
| 3 | 其余公网 | HACS / GitHub / 更新 | **是**（ACL 3001 → permit node → `.230`） |

补充：

- PBR/ACL 只认 IP；域名访问取决于解析结果。Nginx 反代时 Hass 对端多为 `.241`。
- 手机开 PBR 时同样走 3002，避免访问家里设备绕 `.230`。
- mihomo 的 `DIRECT` **不能**替代交换机 3002。

默认例外 CIDR（Agent `.env`）：`ROUTE_BYPASS_CIDRS=192.168.0.0/16,10.0.0.0/8`。

## 不对称故障对照

```text
去程（正常）:  办公室 .5.x / WG 10.0.0.x  → 隧道/LAN → Hass .249
回程（无 3002）: Hass → 只命中 3001 → next-hop .230 → 断或异常
回程（有 3002）: Hass → 命中 deny node → 1.254 → IPsec/WG → 对端
```

曾踩坑：Hass 开「错误分路」后旧卡片「客厅电视上网」显示设备不可用 —— 根因是 Telnet `.254:23` 被 PBR 劫持。
